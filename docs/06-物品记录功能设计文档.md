# 物品记录功能设计文档

> 实现状态：VERIFIED（本地全量检查与浏览器流程通过）
>
> 部署状态：PREPARED（未部署；真实 PostgreSQL 17 恢复等待 CI）
>
> 功能 ID：`inventory`
>
> 适用范围：个人工作台 Web 首版，PC 与 Android 浏览器/PWA 共用同一套数据与接口

## 1. 功能目标

物品记录用于回答三个简单问题：我有什么、放在哪一组、现在有多少。它不是仓储或进销存系统，不记录采购单、金额、条码、供应商和复杂出入库流水。

首版支持：

- 记录物品名称、用途、备注和非负整数数量。
- 为物品选择一个分组，也可以保持“无分组”。
- 直接在列表中用减号和加号将数量按 1 快速调整。
- 数量减到 0 时保留物品，明确显示为“数量为 0”，不自动归档或删除。
- 编辑、归档、恢复和永久删除物品；只有已归档物品可以永久删除。
- 新建、重命名和删除分组；删除分组时，其物品全部转为“无分组”，物品本身不删除。
- 按名称、用途或备注搜索，按分组和数量状态筛选。
- 接入工作台功能目录、侧边栏、快速创建、总览、最近更新和全局搜索。

## 2. 非目标

首版不实现：

- 多级分组、一个物品同时属于多个分组、标签体系。
- 金额、购买时间、保质期、借出人、图片、附件和条码。
- 库存变更流水、批次、仓库、单位换算或自动补货。
- 因数量为 0 自动删除、归档或隐藏物品。

## 3. 核心规则

### 3.1 物品

| 字段     | 规则                                  |
| -------- | ------------------------------------- |
| 物品名称 | 必填，1–120 个字符                    |
| 物品用途 | 可选，最多 500 个字符                 |
| 备注     | 可选，最多 2000 个字符                |
| 数量     | 必填，0–999999 的整数；新建表单默认 1 |
| 分组     | 可选；未选择时为“无分组”              |
| 状态     | `active` 或 `archived`                |

物品名称不要求全局唯一。同名物品可以因用途、分组或备注不同而分别记录。

### 3.2 分组

- 分组名称必填，1–80 个字符，忽略首尾空格后不能重名。
- 首版只有一层分组，例如“收纳箱”“书桌抽屉”“宿舍常用”。
- “无分组”是界面中的虚拟分组，不在数据库中创建记录。
- 删除真实分组时，在同一数据库事务中把关联物品的 `group_id` 置空，再删除分组。
- 归档物品仍保留原分组关系；删除该分组时，归档物品也一并转为无分组。

### 3.3 数量调整

- 列表中的 `−` 和 `+` 每次分别调整 `-1` 或 `+1`。
- 后端使用原子更新，允许连续点击，不依赖页面中的旧版本号计算新值。
- 数量已经为 0 时，减号不可用；即使收到减量请求，后端也把结果限制为 0。
- 每次数量变化都会增加记录版本并更新时间，但不会改变归档状态。
- 已归档物品不能调整数量；应先恢复。

### 3.4 生命周期

```text
使用中 --归档--> 已归档 --恢复--> 使用中
                         \
                          \--永久删除（不可恢复）
```

归档不等于数量为 0。数量为 0 的物品仍属于使用中记录，并可直接补回数量。

## 4. 页面布局

### 4.1 页面顶部

- 页面标题由工作台顶栏提供，不增加占空间的大型功能说明横幅。
- 右上角提供“管理分组”和“添加物品”。
- 第一行是搜索框、状态切换和“卡片/列表”视图切换。
- 第二行是横向可滚动的分组筛选：所有分组、无分组、各真实分组；右侧提供“分组/全部”排列切换。
- 汇总条显示当前筛选范围的“物品种类”“数量合计”“数量为 0”。

### 4.2 PC 布局

默认使用高密度的物品台账网格，同一行可展示更多卡片。可切换为单行列表，视图选择仅保存在当前浏览器，不进入物品数据和备份。每条记录包含：

- 分组、物品名称、用途和备注摘要。
- 突出的当前数量。
- 可直接操作的减号与加号。
- 编辑和归档操作。

卡片数量控制区采用黄铜色数量轨道作为识别特征，其他区域继续使用工作台现有主题变量，确保深色、浅色和后续主题都能统一覆盖。

排列规则：

- 默认“分组”：同组物品进入同一分区，分组顺序沿用分组列表，无分组放在最后，组内按最近更新优先。
- 切换“全部”：不显示分区，所有物品统一按最近更新优先排列，同组物品可以分散。
- “所有分组”仅代表筛选范围，“分组/全部”仅代表排列方式，两者不混用。

### 4.3 Android/窄屏布局

- 工具栏纵向排列，分组筛选允许横向滚动。
- 卡片视图改为单列，名称和说明在上，数量步进器占据卡片底部的完整宽度。
- 列表视图使用两行紧凑结构，第一行是名称和操作，第二行是摘要和数量步进器。
- 减号、加号和主要操作按钮最小触控区域为 44×44 像素。
- 新建、编辑和分组管理继续使用现有全屏式移动端模态框，标题、关闭按钮和提交区保持固定。

### 4.4 空状态

- 没有物品：提示添加第一件物品。
- 搜索或筛选无结果：提示清除筛选，不误导用户新建重复记录。
- 数量为 0：仍显示记录和加号，强调它可以直接补回。
- 已归档：显示恢复和永久删除，不显示数量步进器。

## 5. 操作流程

### 5.1 添加物品

1. 点击“添加物品”。
2. 输入名称，可选用途、备注和分组；数量默认 1，可改为 0。
3. 保存后关闭弹窗，新记录出现在当前列表中。
4. 每次重新打开新建弹窗都使用空白初始值，不保留上次填写内容。

### 5.2 管理分组

1. 点击“管理分组”。
2. 可直接添加分组，并查看每组包含的物品种类数。
3. 可重命名分组。
4. 删除分组前明确提示“其中物品将移到无分组”；确认后仅删除分组。

### 5.3 快速调整数量

1. 在物品卡片上点击 `−` 或 `+`。
2. 页面立即给出视觉反馈，并向服务器发送原子调整请求。
3. 请求完成后以服务器结果为准刷新相关汇总、总览和最近更新。
4. 失败时恢复服务器数据并显示错误提示。

## 6. 数据模型

### 6.1 `inventory_groups`

| 字段         | 类型        | 说明                       |
| ------------ | ----------- | -------------------------- |
| `id`         | UUID        | 主键                       |
| `name`       | text        | 分组名称，大小写不敏感唯一 |
| `position`   | integer     | 稳定排序位置               |
| `version`    | integer     | 乐观锁版本                 |
| `created_at` | timestamptz | 创建时间                   |
| `updated_at` | timestamptz | 更新时间                   |

### 6.2 `inventory_items`

| 字段         | 类型        | 说明                       |
| ------------ | ----------- | -------------------------- |
| `id`         | UUID        | 主键                       |
| `group_id`   | UUID / null | 可选分组，删除分组时置空   |
| `name`       | text        | 物品名称                   |
| `purpose`    | text        | 用途                       |
| `note`       | text        | 备注                       |
| `quantity`   | integer     | 非负整数                   |
| `status`     | text        | `active` / `archived`      |
| `version`    | integer     | 编辑、归档和数量变化的版本 |
| `created_at` | timestamptz | 创建时间                   |
| `updated_at` | timestamptz | 更新时间                   |

数据库迁移使用新的 `023-inventory`，不修改任何已经发布的迁移。

## 7. 接口边界

物品接口：

- `GET /api/v1/inventory-items`
- `GET /api/v1/inventory-items/:id`
- `POST /api/v1/inventory-items`
- `PUT /api/v1/inventory-items/:id`
- `POST /api/v1/inventory-items/:id/adjust-quantity`
- `POST /api/v1/inventory-items/:id/archive`
- `POST /api/v1/inventory-items/:id/restore`
- `DELETE /api/v1/inventory-items/:id`

分组接口：

- `GET /api/v1/inventory-groups`
- `POST /api/v1/inventory-groups`
- `PUT /api/v1/inventory-groups/:id`
- `DELETE /api/v1/inventory-groups/:id`

所有接口复用工作台固定账户、会话、同源校验与 CSRF 规则，不新增注册、用户或权限模型。

## 8. 工作台集成

- 功能目录名称：物品记录。
- 分类：工具。
- 侧边栏默认显示，可在设置中隐藏和排序。
- 快速创建：打开“添加物品”弹窗。
- 全局搜索：搜索物品名称、用途、备注和分组名称。
- 最近更新：展示最近修改的使用中物品。
- 总览：展示使用中物品种类数、数量合计和数量为 0 的种类数。
- 普通新增功能只增加本功能切片和固定注册项，不改写工作台外壳或其他已完成功能。
