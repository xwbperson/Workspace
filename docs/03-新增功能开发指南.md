# 新增功能开发指南

## 1. 目标

新增普通功能时，工作台主体只需要知道“它叫什么、从哪里进入、能贡献哪些公共信息”，不应了解功能内部表结构或页面状态。功能在代码上是独立切片，在使用感受上仍然是同一个应用：共享导航、视觉规范、搜索、总览、通知、登录态和响应式行为。

首个参考切片是“倒计时”。它不是插件，也不会单独安装或部署；所有功能仍随同一版本一起构建和发布。

## 2. 倒计时参考切片

### 2.1 前端文件

```text
apps/web/src/features/countdowns/
├── api.ts
├── CountdownPage.tsx
├── components/
│   ├── CountdownDisplay.tsx
│   └── CountdownForm.tsx
└── index.ts
```

- `api.ts` 只包装该功能的 HTTP 调用和查询缓存键。
- `CountdownPage.tsx` 负责列表、详情和操作编排。
- `components/` 保存功能私有组件，不让工作台壳直接引用。
- `index.ts` 是功能对外公开出口。

### 2.2 后端文件

```text
apps/api/src/features/countdowns/
├── repository.ts
├── service.ts
├── routes.ts
├── contributions.ts
└── index.ts
```

- `repository.ts` 只负责 SQL 与行对象映射。
- `service.ts` 负责输入归一化、业务规则和乐观并发控制。
- `routes.ts` 定义稳定 HTTP 契约，并显式声明认证策略。
- `contributions.ts` 把功能数据转换为工作台公共模型。
- `index.ts` 只导出其他功能确实需要的稳定接口。

数据库变更放在新的迁移文件中。已发布迁移不可修改，也不能让功能直接读取另一个功能的私有表。

## 3. 固定注册点

一个新功能通常只修改以下三个主体文件：

| 注册点                                 | 新增内容                         | 不应放入的内容               |
| -------------------------------------- | -------------------------------- | ---------------------------- |
| `apps/web/src/app/feature-catalog.ts`  | 名称、图标、分类、路由、能力声明 | 页面状态、数据请求、业务规则 |
| `apps/web/src/app/feature-routes.tsx`  | 懒加载页面路由                   | 功能页面实现                 |
| `apps/api/src/app/feature-registry.ts` | 路由注册、聚合贡献、后台任务工厂 | 功能业务逻辑或 SQL           |

如果一个功能不支持搜索、通知或总览摘要，就不声明相应能力，不要创建空实现。只有两个以上功能出现同一真实需求时，才考虑扩展共享平台契约。

## 4. 功能怎样进入总览和其他公共区域

后端 `WorkbenchContributionProvider` 是工作台与功能之间的公共协议。功能可以按需提供：

- `getFocusCandidates`：当前关注候选；
- `getUpcoming`：未来时间轨道条目；
- `getRecent`：最近修改内容；
- `overviewBlocks`：可显示、隐藏和排序的功能摘要块；
- `search`：统一搜索结果；
- `quickCreateActions`：快速创建入口。

工作台服务负责聚合、排序、超时和局部错误隔离。总览页只渲染公共 DTO，不导入倒计时组件，因此用户看见的是统一页面，而不是拼接的多个小应用。

通知同样写入共享通知仓库。功能负责产生稳定的通知 ID、标题、时间和目标路由；工作台负责展示与已读状态。

## 5. 新功能实施步骤

1. 明确功能自己的实体、状态和归档规则。
2. 新建前后端功能目录，并只从各自 `index.ts` 暴露稳定接口。
3. 新建数据库迁移和仓库层测试。
4. 完成带认证声明、输入 Schema 和错误模型的 API。
5. 完成功能页面的加载、空数据、局部失败、保存中和冲突状态。
6. 按实际能力实现公共贡献，不直接修改总览或搜索页面。
7. 更新三个固定注册点。
8. 更新 OpenAPI 契约并运行完整质量门。

```powershell
npm run openapi:generate
npm run check
```

## 6. 验收清单

- 新功能入口同时适用于 PC 侧栏、功能汇总页和 Android 布局。
- 刷新功能详情路由不会丢失页面状态或跳回首页。
- 未登录请求被拒绝，所有写操作通过 Origin 与 CSRF 校验。
- 功能失败不会阻断总览中其他区域。
- 功能数据进入完整数据库备份，恢复后数量和关键不变量一致。
- 静态功能目录、前后端注册表和 API 契约有自动化测试。
- 添加功能没有改写已完成功能的内部代码。

满足代码检查只能标记实现范围为 `VERIFIED`；交互是否符合个人习惯仍需要实际使用验收。
