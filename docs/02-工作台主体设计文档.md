# 个人工作台主体设计文档

> 状态：`PREPARED`<br>
> 更新日期：2026-08-11<br>
> 适用阶段：Web/PWA 首版产品设计<br>
> 关联文档：[01-架构文档](./01-架构文档.md)<br>
> 读者：项目所有者、产品设计者、前端开发者、后端开发者、AI 开发代理

本文定义个人工作台主体的产品能力、信息架构、页面布局、交互规则和功能接入约束。工作台主体包括应用壳、总览页、功能汇总页以及搜索、快速创建、通知、个性化和系统状态等全局能力；任务、计划、倒计时、笔记等具体功能的完整页面和业务规则不在本文展开，由后续功能模块设计文档分别定义。

系统只供个人使用，首版只有一个固定 `owner` 账户。提供登录、退出、修改密码和长期会话，但不提供注册、多用户、角色或按功能分配权限。登录页预填固定用户名；在个人设备勾选“记住此设备”后，通常不需要频繁重新输入密码。

本文是设计基线，不代表页面已经实现、运行验证或正式验收。文中的布局用于约束信息层级和响应式行为，不要求不同设备使用完全相同的控件位置。

## 1. 设计目标

工作台主体需要同时解决以下问题：

1. 用户进入系统后，能够立即看见当前最值得关注的信息，而不是先进入某个具体功能。
2. 支持展示任务、计划、倒计时、目标、笔记等功能的部分内容，但保持统一的阅读和操作体验。
3. 提供一个完整的功能汇总页，使用户能够清楚知道系统当前有哪些已注册并可发现的功能。
4. 所有功能默认进入主导航，用户可以隐藏低频功能并按自己的习惯调整顺序。
5. 新增功能主要增加自身代码和固定注册项，不要求重写总览页、侧边栏或功能汇总页。
6. PC、平板和 Android 手机共用同一套信息架构、功能名称、数据和 Session 规则，仅根据可用空间调整布局。
7. 单个功能加载失败时，工作台主体和其他功能仍可继续使用。

### 1.1 设计原则

- **当前事项优先**：总览页首先回答“我现在应该关注什么”。
- **完整发现能力**：功能汇总页必须列出当前工作区的全部可见功能，不能依赖用户记住入口。
- **默认完整、按需整理**：全部已发布功能默认显示在侧边栏，用户可以在设置中隐藏或调整顺序；功能汇总页始终保留完整入口。
- **统一体验优先**：总览中的摘要由工作台统一组织，避免形成彼此风格不同的模块拼接页。
- **渐进展开**：总览只展示摘要，点击后进入对应功能查看和处理完整内容。
- **布局适配而非页面复制**：不同窗口共用内容优先级，允许改变导航形态、列数和详情呈现方式。
- **可恢复失败**：加载、空数据、Session 失效和局部错误都必须给出明确状态和下一步操作。

## 3. 工作台主体信息架构

工作台主体固定提供两个一级业务页面，以及若干全局入口。

```text
个人工作台
├── 总览
│   ├── 当前关注
│   ├── 即将到来
│   ├── 功能摘要
│   ├── 最近内容
│   └── 异常与提醒
├── 功能
│   ├── 常用功能
│   ├── 全部功能
│   ├── 分类筛选
│   └── 功能搜索
├── 全局搜索
├── 快速创建
├── 通知中心
├── 系统状态
└── 设置与账户
```

### 3.1 主路由建议

| 页面或入口 | 建议路由                    | 说明                                            |
| ---------- | --------------------------- | ----------------------------------------------- |
| 登录页     | `/login`                    | 固定 `owner` 账户登录；已登录时跳回原目标或总览 |
| 总览页     | `/`                         | 登录后的默认页面                                |
| 功能汇总页 | `/features`                 | 展示当前工作区的全部可见功能                    |
| 全局搜索   | `/search` 或全屏搜索层      | 手机使用独立页面，宽屏可使用覆盖层              |
| 通知中心   | `/notifications` 或侧边抽屉 | 查看全部通知和处理状态                          |
| 设置       | `/settings`                 | 工作台偏好、账户、备份和系统设置                |
| 具体功能   | `/features/<feature-id>`    | 由对应功能模块注册                              |

路由名称只作为实现建议。无论最终采用页面还是覆盖层，直接链接、刷新恢复和浏览器前进后退都必须保持有效。

### 3.2 固定账户登录与长期会话

登录页位于工作台应用壳之前，保持简单，不承担产品介绍或注册引导。

```text
┌────────────────────────────┐
│         个人工作台          │
│                            │
│  账户  owner（固定）        │
│  密码  [______________]    │
│  ☑ 记住此设备              │
│                            │
│       [ 登录工作台 ]        │
└────────────────────────────┘
```

登录规则：

- 用户名固定为 `owner` 并默认填充，用户通常只输入密码。
- 不显示注册、切换账户、第三方登录或邮件找回密码入口。
- “记住此设备”在个人设备场景默认勾选。它表示为当前浏览器创建长期登录会话，不表示识别硬件设备，也不使用设备指纹或 IP 绑定。
- 长期会话的空闲期限为 180 天，活动时至多每 24 小时续展一次；绝对期限在登录时固定为 365 天，不能续展。持久 Cookie 的剩余时间不得超过服务端空闲期限和绝对期限中的较早者。
- 未勾选时使用临时登录：服务端空闲 12 小时、绝对 24 小时，Cookie 不设置持久过期属性。浏览器会话恢复可能在重开后保留临时 Cookie，最终始终以服务端期限为准。
- 服务端在登录时生成首个 Session 标识，之后首个距离上次轮换满 7 天的有效请求触发轮换。旧标识只再接受 2 分钟以容纳并发请求，且不能触发二次轮换；主动退出、撤销会话、修改或重置密码会立即撤销同一 Session Family 的新旧标识。
- Session 持久化到 PostgreSQL，应用或服务器正常重启不会自动退出。
- Session Cookie 使用 `Secure`、`HttpOnly`、`SameSite=Lax`，令牌不写入 Web Storage。
- 登录输入框支持密码管理器的 `username` 和 `current-password` 自动填充，允许粘贴密码，不通过自定义键盘妨碍系统自动填充。
- 登录失败使用统一提示，不能区分账户不存在和密码错误；连续失败执行限速和递增等待。
- 原目标路由只允许站内相对路径；登录成功后回到原目标，否则进入总览。
- Session 失效时保留未提交表单草稿的能力由具体功能设计，主体负责转到登录页并带回安全的原目标。
- 每个浏览器首次使用需要登录一次，之后保持自己的登录会话。清除站点数据、主动退出、撤销会话、修改或重置密码、空闲超时或达到绝对期限后需要重新登录。同一设备的不同浏览器是不同会话；再次登录会产生另一条会话。

账户入口只提供：修改密码、查看登录会话、为会话改名、撤销单个会话、退出当前会话和退出其他会话。每条会话显示粗粒度客户端标签、创建时间、最近活动时间和到期状态；标签只用于识别，不作为安全凭据。忘记密码时使用服务器管理命令重置，不建设邮件找回流程。修改或重置密码后撤销全部已有 Session Family。

## 4. 应用壳设计

应用壳是所有主体页面和功能页面共享的稳定区域。它只负责导航、定位和全局操作，不承载具体功能业务。

### 4.1 应用壳组成

```text
WorkbenchShell
├── NavigationArea       主体导航和常用功能
├── PageHeaderArea       页面位置、标题和页面级操作
├── GlobalSearchEntry    全局搜索和命令入口
├── QuickCreateEntry     全局快速创建
├── ContentArea          总览、功能汇总或具体功能页面
├── NotificationEntry    通知和待处理状态
├── SystemStatusEntry    备份、同步和服务状态
└── AccountEntry         账户、主题和设置
```

应用壳使用固定插槽而不是固定设备布局。PC 可以将导航放在左侧，手机可以将核心导航放在底部；具体功能只接收内容区域，不依赖导航位于哪个方向。

### 4.2 PC 端应用壳

```text
┌────────────────┬──────────────────────────────────────────────────────────┐
│ 工作台标识      │ 页面位置 / 页面标题        搜索  快速创建  通知  账户      │
├────────────────┼──────────────────────────────────────────────────────────┤
│ 总览            │                                                          │
│ 功能            │                                                          │
│                 │                                                          │
│ 常用功能        │                      页面内容区                           │
│ · 功能 A        │                                                          │
│ · 功能 B        │                                                          │
│ · 功能 C        │                                                          │
│                 │                                                          │
│                 │                                                          │
│ 系统状态        │                                                          │
│ 设置            │                                                          │
└────────────────┴──────────────────────────────────────────────────────────┘
```

建议规则：

- 左侧栏展开宽度为 `224–240px`，可折叠为约 `64–72px` 的图标栏。
- 顶部栏高度约 `56–64px`，保持所有页面的全局操作位置一致。
- 内容区宽度不强制铺满超宽屏；总览和功能汇总页建议设置最大内容宽度并居中。
- “总览”和“功能”是固定入口，不能被用户取消。
- “常用功能”只展示用户固定的功能，默认最多直接显示 6 个，超出后使用“更多常用功能”。
- 设置、账户和系统状态放在侧边栏底部，避免与业务功能混在一起。
- 当前页面必须同时通过选中状态和页面标题体现，不能只依赖颜色。

### 4.3 平板和窄桌面应用壳

```text
┌────────┬─────────────────────────────────────────────┐
│ 图标栏 │ 页面标题              搜索  创建  通知       │
├────────┼─────────────────────────────────────────────┤
│ 总览   │                                             │
│ 功能   │                 页面内容区                  │
│ 常用   │                                             │
│ 设置   │                                             │
└────────┴─────────────────────────────────────────────┘
```

- 导航默认收缩为图标栏，点击或悬停不能成为查看名称的唯一方式，应支持展开或显示文本提示。
- 总览可以使用两列，功能汇总页根据实际宽度使用 3–4 列方格。
- 功能内部是否使用列表—详情双栏，由对应功能模块设计文档决定。

### 4.4 Android 手机端应用壳

```text
┌────────────────────────────┐
│ 页面标题       搜索  通知   │
├────────────────────────────┤
│                            │
│         页面内容区          │
│                            │
│                            │
│                 ＋快速创建  │
├────────────────────────────┤
│   总览    功能    搜索    我的│
└────────────────────────────┘
```

建议规则：

- 底部导航固定提供“总览、功能、搜索、我的”四个入口。
- “我的”包含账户、设置、备份状态、主题和其他低频全局入口。
- 快速创建使用浮动按钮或底部导航上方的固定主操作；展开后显示各功能注册的创建动作。
- 页面标题和主要状态位于顶部栏，顶部栏不堆放低频操作。
- 进入具体功能后，底部导航可以保留；进入沉浸式编辑页面时允许暂时隐藏，但必须提供明确返回路径。
- 内容区域必须避开系统安全区、软键盘和底部导航。

### 4.5 响应式分级

布局根据可用窗口宽度决定，不根据设备名称硬编码。

| 可用宽度      | 主导航             | 总览布局               | 功能方格 |
| ------------- | ------------------ | ---------------------- | -------- |
| `< 600px`     | 底部导航           | 单列                   | 2 列     |
| `600–839px`   | 图标导航栏         | 单列或紧凑双列         | 3 列     |
| `840–1199px`  | 图标栏或可折叠侧栏 | 双列                   | 3–4 列   |
| `1200–1599px` | 展开侧栏           | 主次双列               | 4–5 列   |
| `≥ 1600px`    | 展开侧栏           | 主次双列，限制最大宽度 | 5–6 列   |

断点是设计基线，不要求每个组件都在同一像素同时变化。实现时应优先使用容器实际宽度判断局部布局。

## 5. 总览页设计

### 5.1 页面定位

总览页是登录后的默认页面，目标不是展示系统所有数据，而是以最少阅读成本回答以下问题：

1. 当前最需要关注什么？
2. 接下来会发生什么？
3. 各功能中有哪些值得查看的变化？
4. 有没有逾期、失败或需要处理的异常？
5. 怎样最快开始一项操作？

总览页只展示可操作摘要。完整列表、复杂筛选、批量操作和详细编辑必须进入对应功能完成。

### 5.2 内容区域

总览由固定核心区和可配置功能摘要区组成。

| 区域       | 是否固定     | 内容                                     | 主要操作             |
| ---------- | ------------ | ---------------------------------------- | -------------------- |
| 页面抬头   | 是           | 日期、欢迎信息、数据更新时间             | 刷新、编辑总览       |
| 当前关注   | 是           | 正在进行或优先级最高的少量事项           | 继续、查看来源       |
| 即将到来   | 是           | 临近任务、计划、日程、倒计时的统一时间流 | 查看全部、打开来源   |
| 快速创建   | 是           | 最近使用和常用创建动作                   | 新建任务、记录等     |
| 功能摘要   | 否           | 支持摘要能力的功能所提供的部分内容       | 打开功能、查看全部   |
| 最近内容   | 否           | 最近查看或修改的记录                     | 继续查看或编辑       |
| 异常与提醒 | 有内容时显示 | 逾期、同步失败、备份异常、功能错误       | 处理、重试、查看详情 |

固定核心区保证总览始终具有一致用途。功能摘要区由用户决定显示哪些模块及其顺序，但首版不提供任意尺寸缩放和自由画布。

### 5.3 PC 总览布局

```text
┌──────────────────────────────────────────────────────────────────────────┐
│ 总览 · 8 月 11 日                              最后更新 10:30  编辑总览  │
├───────────────────────────────────────────────┬──────────────────────────┤
│ 当前关注                                      │ 快速创建                 │
│ 当前事项 / 下一步 / 继续操作                   │ ＋任务  ＋记录  ＋其他    │
├───────────────────────────────────────────────┼──────────────────────────┤
│ 即将到来                                      │ 进展摘要                 │
│ 09:00 计划事项                                │ 本周目标 / 完成情况       │
│ 明天   任务截止                                ├──────────────────────────┤
│ 3 天后 倒计时                                 │ 异常与提醒               │
│ 查看全部                                      │ 逾期 / 备份 / 同步状态    │
├───────────────────────────────────────────────┴──────────────────────────┤
│ 功能摘要                                                                │
│ ┌────────────────────┐ ┌────────────────────┐ ┌────────────────────┐     │
│ │ 任务摘要            │ │ 倒计时摘要          │ │ 笔记摘要            │     │
│ │ 今日与近期内容      │ │ 最近的关键日期      │ │ 最近编辑内容        │     │
│ └────────────────────┘ └────────────────────┘ └────────────────────┘     │
├──────────────────────────────────────────────────────────────────────────┤
│ 最近内容                                                                │
└──────────────────────────────────────────────────────────────────────────┘
```

布局规则：

- 使用 12 列内容网格，主列约占 8 列，辅助列约占 4 列。
- “当前关注”和“即将到来”优先于统计数字和最近内容。
- 功能摘要区允许 2–3 列，但同一行高度不强制完全一致。
- 只有真正可点击、可移动或具有独立状态的摘要才使用卡片边界；普通列表使用区块和分隔线，避免满屏方框。
- 异常区没有内容时不保留空卡片，释放给其他摘要使用。
- 超宽屏保持合理阅读宽度，不通过无限增加列数塞入更多内容。

### 5.4 手机总览布局

```text
┌────────────────────────────┐
│ 总览 · 8 月 11 日      编辑 │
├────────────────────────────┤
│ 当前关注                    │
│ 当前事项 / 下一步           │
├────────────────────────────┤
│ 即将到来                    │
│ 按时间排列的统一列表         │
│ 查看全部                    │
├────────────────────────────┤
│ 异常与提醒（有内容时）       │
├────────────────────────────┤
│ 功能摘要                    │
│ 任务摘要                    │
│ 倒计时摘要                  │
│ 笔记摘要                    │
├────────────────────────────┤
│ 最近内容                    │
└────────────────────────────┘
```

布局规则：

- 保持“当前关注 → 即将到来 → 异常 → 功能摘要 → 最近内容”的纵向优先级。
- 快速创建由全局按钮承担，不在页面顶部重复放置大型创建区域。
- 摘要默认单列显示；横向滚动仅适用于短小、可预期数量的指标，不用于长列表。
- 每个摘要首屏只显示 2–5 条关键内容，提供“查看全部”进入来源功能。
- 页面返回后恢复原滚动位置和已展开状态。

### 5.5 当前关注

“当前关注”是总览中优先级最高的内容，但它不是自动把所有高优先级数据混在一起。

首版按以下顺序选择内容：

1. 用户手动设为“当前关注”的事项。
2. 正在进行且存在明确下一步的事项。
3. 已开始或即将开始的计划。
4. 距离截止时间最近且风险较高的事项。
5. 没有可用内容时显示快速开始引导。

当前关注最多突出 1 个主事项，并允许附带 2–3 个候选事项。自动选择结果必须显示来源功能，用户可以手动替换或清除。

总览中的“继续”只负责打开来源功能或原始记录，不直接完成、删除或编辑业务数据。总览的聚合内容保持只读；需要修改业务状态时，必须进入对应功能并由该功能自己的公开命令处理。全局快速创建属于独立的创建入口，不改变总览摘要的只读边界。

### 5.6 即将到来

“即将到来”将多个功能中的时间信息映射为统一时间流，例如：

- 任务截止时间。
- 计划开始或结束时间。
- 日程事件。
- 倒计时目标时间。
- 提醒触发时间。

统一条目至少包含：

| 字段 | 说明                               |
| ---- | ---------------------------------- |
| 类型 | 任务、计划、日程、倒计时或其他来源 |
| 标题 | 用户可识别的内容名称               |
| 时间 | 绝对时间或可解释的相对时间         |
| 状态 | 正常、临近、逾期、已完成等         |
| 来源 | 对应功能名称和记录标识             |
| 跳转 | 打开原始记录或来源功能             |

默认按实际时间升序排列。相同时间下可按用户明确优先级排序；不能用颜色代替文字状态。

### 5.7 功能摘要

只有声明了“可提供总览摘要”的功能才能进入功能摘要区。普通功能可以只出现在功能汇总页，不需要为了进入总览而制造无意义统计。

首版支持以下标准摘要类型：

| 摘要类型 | 适用内容                   | 示例                     |
| -------- | -------------------------- | ------------------------ |
| 关键数字 | 单个或少量可解释指标       | 未完成任务数、本周记录数 |
| 进度     | 有明确总量和目标的数据     | 目标进度、阅读进度       |
| 近期列表 | 少量最新或临近记录         | 最近笔记、近期计划       |
| 时间节点 | 与日期或剩余时间相关的内容 | 倒计时、纪念日           |
| 状态摘要 | 系统或功能运行状态         | 最近备份、导入任务状态   |

摘要必须满足以下约束：

- 标题明确说明内容范围。
- 显示数据更新时间；过期数据需要标记。
- 提供来源功能和“查看全部”入口。
- 默认不在总览中直接提供复杂编辑。
- 只显示当前工作区的数据。
- 单个摘要失败时显示局部重试，不影响其他摘要。
- 自定义可视化只有在标准摘要无法表达真实需求时才增加，并需遵守统一间距、字体和状态规范。

### 5.8 总览编辑

总览页提供“编辑总览”模式，首版支持：

- 显示或隐藏可选功能摘要。
- 调整可选摘要顺序。
- 恢复默认布局。
- 预览修改结果。

首版不支持：

- 任意像素拖放。
- 用户自由改变卡片宽高。
- 在手机和 PC 分别维护完全不同的内容集合。
- 将完整功能页面嵌入总览。

布局偏好存储的是语义顺序和显示状态，而不是设备相关坐标，使同一配置能够在不同宽度下合理重排。

### 5.9 总览状态设计

| 状态         | 表现                                           | 用户可执行操作           |
| ------------ | ---------------------------------------------- | ------------------------ |
| 首次使用     | 说明总览用途，提供添加第一个事项和查看功能入口 | 快速创建、打开功能页     |
| 正在加载     | 保留整体结构，使用与最终内容近似的骨架         | 等待或取消刷新           |
| 部分失败     | 仅失败摘要显示原因和重试，其他内容正常显示     | 重试、打开来源功能       |
| 全部失败     | 保留应用壳，说明连接或 Session 状态            | 重试、重新登录、查看状态 |
| 无数据       | 说明为什么为空，不使用庆祝式或营销式文案       | 创建内容、调整筛选       |
| 数据过期     | 显示最后更新时间和过期标记                     | 手动刷新                 |
| Session 失效 | 保存安全的站内返回目标并转到登录页             | 重新登录                 |

## 6. 功能汇总页设计

### 6.1 页面定位

功能汇总页是当前工作区的完整功能目录。它必须让用户清楚看到哪些功能已经发布、各功能用于做什么、哪些是常用功能以及哪些功能暂时不可进入。

功能汇总页不是应用商店，不展示安装、版本和依赖关系。功能是否进入该页面，由“已注册、当前环境允许发现”共同决定；是否能够进入和正常使用，再由生命周期、配置状态和运行状态决定。固定 `owner` 登录后拥有全部业务功能，不再按用户过滤功能。

本文使用以下三个集合，后续页面数量、搜索范围和验收均按同一口径处理：

| 集合       | 定义                                              | 用途                                 |
| ---------- | ------------------------------------------------- | ------------------------------------ |
| 已注册功能 | 已进入编译期功能目录并具有唯一 `featureId` 的功能 | 开发和一致性校验，不直接等于可见     |
| 可见功能   | 已注册且当前环境允许发现的功能                    | 功能汇总页、功能数量和功能搜索的范围 |
| 可进入功能 | 可见，并且生命周期和运行状态允许打开的功能        | 导航和方格主操作的范围               |

“全部功能”表示“当前工作区的全部可见功能”，不是代码仓库中的所有计划功能。开发中功能在生产环境默认不可发现；只有明确开启预览且不会误导用户时，才以“开发中”或“预览”状态显示。

### 6.2 页面内容

```text
功能汇总页
├── 页面标题和功能数量
├── 功能搜索
├── 分类筛选
├── 常用功能
├── 全部功能方格
└── 功能状态说明
```

推荐分类采用用户能够理解的用途名称，而不是技术模块名称。首版可以从以下分类中按真实功能取用：

- 计划与执行。
- 记录与知识。
- 时间与提醒。
- 目标与复盘。
- 文件与收藏。
- 工具。

分类数量不宜超过 6 个。某一分类只有一个功能时，可以不单独形成视觉分区，而只作为筛选条件。

### 6.3 PC 功能汇总布局

```text
┌──────────────────────────────────────────────────────────────────────────┐
│ 功能（12 个可见功能）                           搜索功能名称或用途        │
│ [全部] [常用] [计划与执行] [记录与知识] [时间与提醒] [工具]              │
├──────────────────────────────────────────────────────────────────────────┤
│ 常用功能                                                                │
│ ┌──────────────┐ ┌──────────────┐ ┌──────────────┐                      │
│ │ 图标      固定│ │ 图标      固定│ │ 图标      固定│                      │
│ │ 任务          │ │ 笔记          │ │ 倒计时        │                      │
│ │ 一句话说明    │ │ 一句话说明    │ │ 一句话说明    │                      │
│ └──────────────┘ └──────────────┘ └──────────────┘                      │
├──────────────────────────────────────────────────────────────────────────┤
│ 全部功能                                                                │
│ ┌──────────────┐ ┌──────────────┐ ┌──────────────┐ ┌──────────────┐     │
│ │ 功能方格      │ │ 功能方格      │ │ 功能方格      │ │ 功能方格      │     │
│ └──────────────┘ └──────────────┘ └──────────────┘ └──────────────┘     │
└──────────────────────────────────────────────────────────────────────────┘
```

布局规则：

- 方格保持接近正方形，推荐宽高比 `1:1`，极窄宽度下允许略微增高。
- 普通 PC 使用 4–5 列，宽屏最多 6 列；不通过缩小文字无限增加列数。
- 方格是完整点击目标，但内部的固定按钮、状态说明等独立控件不能与打开功能的点击事件冲突。
- 常用功能和全部功能中的同一功能可以重复展示，但“全部功能”必须完整且只出现一次。
- 功能较少时不强行填满整行，保持左对齐和稳定间距。

### 6.4 手机功能汇总布局

```text
┌────────────────────────────┐
│ 功能（12）            搜索  │
│ [全部] [常用] [计划] [记录] │
├────────────────────────────┤
│ 常用功能                    │
│ ┌──────────┐ ┌──────────┐  │
│ │ 任务      │ │ 笔记      │  │
│ │ 简短说明  │ │ 简短说明  │  │
│ └──────────┘ └──────────┘  │
├────────────────────────────┤
│ 全部功能                    │
│ ┌──────────┐ ┌──────────┐  │
│ │ 倒计时    │ │ 目标      │  │
│ └──────────┘ └──────────┘  │
└────────────────────────────┘
```

- 默认使用 2 列方格，较宽手机可以保持 2 列并增加内部留白，不优先切换为 3 列。
- 分类筛选横向滚动时，首尾必须有可见空间，不能让用户误以为只有首屏分类。
- 方格描述最多显示两行，完整说明可以在功能详情提示或进入功能后展示。
- 固定操作始终可以通过方格内按钮或长按菜单完成，不能只依赖悬停。

### 6.5 功能方格规范

每个功能方格包含以下信息：

| 元素     | 必须     | 规则                                                     |
| -------- | -------- | -------------------------------------------------------- |
| 图标     | 是       | 使用统一图标库和线条风格，不允许功能自行使用不协调的大图 |
| 功能名称 | 是       | 使用面向用户的短名称，建议 2–6 个汉字                    |
| 功能说明 | 是       | 一句话说明用途，不写技术实现                             |
| 状态     | 条件显示 | 正常状态不显示；开发中、不可用、需要配置时显示           |
| 数据提示 | 可选     | 最多一个有明确含义的数量或状态，不展示复杂统计           |

方格状态定义：

| 状态         | 表现                                 | 是否允许进入   |
| ------------ | ------------------------------------ | -------------- |
| 可用         | 正常方格                             | 是             |
| 只读         | 显示“只读”，隐藏创建和修改动作       | 是，但只能查看 |
| 需要配置     | 显示说明和配置入口                   | 只进入配置流程 |
| 降级         | 说明受影响能力，保留仍安全可用的入口 | 视状态说明决定 |
| 暂时不可用   | 降低强调并说明原因                   | 否             |
| 预览或开发中 | 明确标记，不与正式可用功能混淆       | 由环境配置决定 |

### 6.6 搜索、筛选和排序

- 搜索范围包括当前工作区可见功能的名称、功能说明和人工配置的关键词。
- 搜索结果实时过滤当前方格，不与内容级全局搜索混淆。
- 分类筛选为单选；“全部”作为固定筛选项。
- 功能汇总页使用功能目录配置顺序，不跟随侧边栏的个人排序变化。
- 搜索无结果时显示当前关键词，并提供清除搜索操作。
- 功能状态过滤不作为首屏主要控件；只有开发中或不可用功能较多时才增加。

### 6.7 侧边栏功能设置

所有已发布并可发现的功能默认显示在侧边栏。用户可以在设置中：

- 上移或下移功能，形成跨设备同步的侧边栏顺序。
- 隐藏不希望长期显示的功能入口。
- 恢复功能目录中的默认顺序。

隐藏功能只影响侧边栏入口，不会停用功能、删除数据，也不会将其从功能汇总页或搜索结果中移除。隐藏状态仍保留排序位置，重新显示后回到原位置。侧边栏顺序不控制总览摘要顺序，两项偏好必须独立保存。

## 7. 全局能力设计

### 7.1 全局搜索

全局搜索同时支持“找功能”和“找内容”，结果按来源分组：

```text
搜索结果
├── 功能
├── 快速动作
├── 任务与计划
├── 笔记与记录
└── 其他功能公开结果
```

要求：

- PC 支持点击搜索框和快捷键打开；手机使用底部“搜索”入口。
- 先显示功能和快速动作，再异步加载各功能内容结果。
- 每条结果显示来源功能、内容类型和必要摘要。
- 搜索层不能直接读取功能数据库或内部状态，只调用公开搜索适配器。
- 某个功能搜索失败时仅影响对应分组。
- 默认不在结果中展示敏感正文，摘要范围由功能自行控制。

### 7.2 快速创建

快速创建聚合各功能公开的创建动作，例如新建任务、快速记录、添加倒计时。

- 动作按“最近使用 → 用户固定 → 默认顺序”排列。
- 首屏显示 4–6 个常用动作，其他动作进入“更多”。
- 简单输入可以在轻量面板完成；复杂表单直接进入对应功能页面。
- 创建成功后显示明确反馈，并提供“查看刚创建内容”。
- 创建失败时保留用户已输入内容，避免关闭面板后丢失。

### 7.3 通知中心

通知中心只承载需要用户知道或处理的事件，不复制所有业务动态。

通知类型包括：

- 时间提醒。
- 逾期或异常提醒。
- 导入、导出、备份和恢复结果。
- 需要用户确认的系统操作。

通知至少包含标题、时间、来源、状态和目标链接。支持单条已读、全部已读和按来源查看；高风险通知不能仅通过红点表达。

### 7.4 系统状态

系统状态入口位于 PC 侧边栏底部和手机“我的”页面中，默认使用低干扰状态表达。

需要展示：

- 当前连接状态。
- 最近一次成功备份时间。
- 是否存在备份、同步或存储异常。
- 应用版本和工作区标识的查看入口。

正常状态不持续占用总览空间。出现异常时，系统状态可以进入总览的“异常与提醒”区域。

### 7.5 设置与个性化

工作台主体相关设置包括：

- 主题模式。
- 侧边栏展开或折叠偏好。
- 常用功能及顺序。
- 总览摘要的显示和顺序。
- 日期、时间和星期显示偏好。
- 通知偏好。
- 数据刷新偏好。

设备特定偏好和跨设备偏好应区分保存。总览内容选择属于跨设备偏好；侧边栏是否折叠属于当前设备偏好。

## 8. 功能接入契约

### 8.1 功能定义

工作台通过编译期固定注册获取功能元数据，不建设运行时插件系统。静态定义描述功能是什么；运行时状态描述功能当前能否进入和正常使用，二者不能混为一个 `status` 字段。

```ts
interface WorkbenchFeatureDefinition {
  featureId: string;
  name: string;
  description: string;
  icon: IconName;
  route: string;
  category: FeatureCategory;
  keywords: string[];
  order: number;
  lifecycle: 'released' | 'preview' | 'in-development';
  discoverableInProduction: boolean;
  canPin: boolean;
  capabilities: {
    focusCandidates?: boolean;
    upcoming?: boolean;
    recent?: boolean;
    overviewBlocks?: boolean;
    search?: boolean;
    quickCreate?: boolean;
    notifications?: boolean;
  };
}

type IconName = string; // 只能使用工作台统一图标注册表中的名称
type FeatureCategory =
  | 'planning-execution'
  | 'notes-knowledge'
  | 'time-reminders'
  | 'goals-review'
  | 'files-collections'
  | 'tools';

interface FeatureRuntimeState {
  featureId: string;
  availability: 'available' | 'needs-config' | 'degraded' | 'unavailable';
  entryMode: 'normal' | 'read-only' | 'configure' | 'disabled';
  enabledCapabilities: Array<'view' | 'create' | 'edit' | 'search' | 'overview'>;
  message?: string;
  actionRoute?: string;
  checkedAt: string;
}
```

运行时展示规则如下：

1. `availability = available`：返回 `entryMode = normal` 和实际可用能力。
2. `availability = needs-config`：返回 `entryMode = configure`，方格主操作只进入 `actionRoute` 指向的配置流程。
3. `availability = degraded`：服务端必须显式返回 `entryMode` 和 `enabledCapabilities`；前端不得根据提示文字自行猜测可用操作。
4. `availability = unavailable`：返回 `entryMode = disabled` 和空能力列表，保留可见方格和说明，但禁止进入业务页面。
5. `lifecycle = in-development`：生产环境默认隐藏；测试或预览环境可以显式开放。

`entryMode` 和 `enabledCapabilities` 描述功能运行状态，不承担用户授权。固定 `owner` 对所有业务功能具有完整权限，但每个 API 仍必须验证有效 Session。

`entryMode` 不是由客户端临时推断，而是服务端根据下表生成并校验。表外组合属于非法状态，功能状态接口必须拒绝返回。

| `availability` | 合法 `entryMode`                    | `enabledCapabilities` 约束                |
| -------------- | ----------------------------------- | ----------------------------------------- |
| `available`    | `normal`                            | 返回实际可用能力                          |
| `needs-config` | `configure`                         | 空列表；只允许进入 `actionRoute` 配置流程 |
| `degraded`     | `normal`、`read-only` 或 `disabled` | 必须显式列出仍安全可用的能力              |
| `unavailable`  | `disabled`                          | 空列表                                    |

服务端为该矩阵提供类型或单元测试。前端只消费已经校验的 `entryMode` 和 `enabledCapabilities`，但仍需处理整个状态接口失败的情况。

新增功能时，主体允许的典型变更只有：

1. 新增功能自己的前后端目录。
2. 在 Web 功能目录表中增加一条静态展示和能力定义。
3. 在 Web 和 API 固定注册点增加一条行为注册，并使用同一个 `featureId`。
4. 按需实现总览摘要、搜索或快速创建公开接口。
5. 增加针对新增功能及其主体接入的测试。

不允许为了新增普通功能重写侧边栏、功能方格组件、总览容器或全局搜索框架。

### 8.2 总览摘要契约

普通功能优先使用工作台提供的标准摘要类型，而不是自行提供任意 UI。

```ts
interface OverviewContributionDefinition {
  featureId: string;
  blockId: string;
  title: string;
  kind: 'metric' | 'progress' | 'recent-list' | 'upcoming' | 'status';
  priority: number;
  defaultVisible: boolean;
  targetRoute: string;
}

interface OverviewBlockProvider {
  definition: OverviewContributionDefinition;
  getData(): Promise<OverviewBlockData>;
}

interface OverviewBlock {
  featureId: string;
  blockId: string;
  title: string;
  priority: number;
  targetRoute: string;
  data: OverviewBlockData;
}

type OverviewBlockData =
  | { kind: 'metric'; value: number | string; label: string; updatedAt: string }
  | { kind: 'progress'; current: number; total: number; label: string; updatedAt: string }
  | { kind: 'recent-list' | 'upcoming'; items: OverviewListItem[]; updatedAt: string }
  | { kind: 'status'; level: 'normal' | 'warning' | 'error'; text: string; updatedAt: string };

interface OverviewListItem {
  id: string;
  title: string;
  subtitle?: string;
  occurredAt?: string;
  targetRoute: string;
}
```

工作台负责统一渲染、布局、加载和错误状态。首版只接受上述标准摘要类型，不允许功能注册任意自定义摘要组件；标准类型无法准确表达的内容暂不进入总览，待出现真实共同需求后再扩展契约。

摘要的“发现”和“取数”使用两条分离通路：

1. `GET /api/v1/workbench/overview/definitions` 在 Session 有效时返回当前工作区可发现的 `OverviewContributionDefinition[]`，不执行 `getData()`，用于“编辑总览”和首次默认配置。
2. `GET /api/v1/workbench/preferences/overview` 返回用户已选择的 `blockId` 顺序；首次没有偏好时，根据定义中的 `defaultVisible` 生成默认值。
3. `PUT /api/v1/workbench/preferences/overview` 保存显示状态和语义顺序，不保存设备坐标。
4. `GET /api/v1/workbench/overview?blockIds=<id1,id2,...>` 固定返回当前关注、即将到来等核心区，并只为请求中已选择且仍然可见的可选摘要执行 `getData()`。

`blockId` 是摘要在整个工作台中的全局唯一标识，固定使用 `<featureId>:<localBlockId>` 格式，例如 `tasks:today`；其中 `localBlockId` 只需在功能内部唯一。定义接口只返回展示元数据，不包含业务数据。客户端不能请求未注册或当前不可见的 `blockId`；服务端忽略非法标识并在响应错误信息中记录。这样编辑模式可以发现隐藏摘要，同时隐藏摘要不会产生持续取数和轮询。

### 8.3 跨功能读取

总览、搜索和通知只调用功能公开的只读查询，不访问功能内部 Repository、数据表、Query Key 或 Store。

```text
功能公开查询 ──→ 工作台聚合服务 ──→ 主体页面
```

首版使用一个工作台聚合接口，避免手机端为每个摘要分别发起大量请求。客户端通过 `blockIds` 传入固定所有者已选择的可选摘要：

```text
GET /api/v1/workbench/overview?blockIds=<id1,id2,...>
```

聚合接口可以并行调用各功能公开查询，并记录每个数据源的成功、失败和更新时间。局部失败不能把整个响应变成不可用。

### 8.4 固定核心区贡献契约

“当前关注、即将到来、最近内容”也是功能公开贡献，不允许工作台直接读取各功能内部数据。支持对应能力的功能实现以下一个或多个只读查询：

```ts
interface WorkbenchContributionProvider {
  featureId: string;
  getFocusCandidates?(): Promise<FocusCandidate[]>;
  getUpcoming?(range: { from: string; to: string }): Promise<UpcomingItem[]>;
  getRecent?(limit: number): Promise<RecentItem[]>;
  overviewBlocks?: OverviewBlockProvider[];
}

interface FocusCandidate {
  featureId: string;
  recordId: string;
  title: string;
  state: 'planned' | 'in-progress' | 'blocked';
  priority?: number;
  startsAt?: string;
  dueAt?: string;
  targetRoute: string;
}

interface UpcomingItem {
  featureId: string;
  recordId: string;
  occurrenceId?: string;
  type: string;
  title: string;
  occursAt: string;
  state: 'normal' | 'near' | 'overdue' | 'completed';
  priority?: number;
  targetRoute: string;
}

interface RecentItem {
  featureId: string;
  recordId: string;
  type: string;
  title: string;
  updatedAt: string;
  targetRoute: string;
}
```

聚合规则固定如下：

- 服务端先验证 Session 和 `workspaceId`，再将结果交给工作台聚合服务。
- 记录唯一键默认为 `featureId + recordId`；重复发生的时间条目再加入 `occurrenceId`。
- `priority` 使用 `0–100` 整数，数值越大表示越重要；缺省值为 `0`，不能用该字段混合表达紧急程度和时间远近。
- 当前关注按“用户手动选择 → 正在进行 → 阻塞风险 → 临近时间 → 功能默认优先级”选择，最终只返回 1 个主事项和最多 3 个候选项。
- 即将到来先按 `occursAt` 升序，再按明确优先级降序，最后按稳定标题或记录标识排序。
- 最近内容按 `updatedAt` 降序，首版最多返回 10 条；同一记录只保留最新一条。
- 某个提供者失败或超时，聚合响应记录对应 `featureId` 的错误，不丢弃其他功能结果。
- 所有条目只提供跳转，不直接执行完成、删除或编辑命令。

功能注册时只注册这一套 `WorkbenchContributionProvider`。聚合服务负责调用 `overviewBlocks` 中每个 `OverviewBlockProvider.getData()`，将 `definition` 与返回数据组合成可序列化的 `OverviewBlock`，再通过 OpenAPI 响应发送给客户端；客户端不会接收函数，也不直接调用功能内部提供者。

### 8.5 全局能力接入契约

全局搜索、快速创建和通知使用最小公开契约接入主体。功能只有在真正实现对应接口后才能把能力声明设为 `true`。

#### 8.5.1 全局搜索提供者

```ts
interface FeatureSearchProvider {
  featureId: string;
  search(input: { query: string; limit: number; cursor?: string }): Promise<SearchResultPage>;
}

interface SearchResultPage {
  items: SearchResultItem[];
  nextCursor?: string;
}

interface SearchResultItem {
  featureId: string;
  recordId: string;
  type: string;
  title: string;
  snippet?: string;
  updatedAt?: string;
  targetRoute: string;
}
```

`GET /api/v1/workbench/search` 负责聚合各功能搜索提供者。服务端在调用提供者前验证 Session 和工作区，每个提供者只返回当前工作区的结果；单个提供者失败时返回该分组错误，不影响其他分组。`snippet` 只允许包含功能认可的短摘要，不默认返回完整正文。

#### 8.5.2 快速创建提供者

```ts
interface QuickCreateProvider {
  featureId: string;
  actions: QuickCreateActionDefinition[];
  execute(input: QuickCreateCommand): Promise<QuickCreateResult>;
}

interface QuickCreateActionDefinition {
  actionId: string;
  label: string;
  mode: 'open-route' | 'inline-title';
  targetRoute: string;
}

interface QuickCreateCommand {
  actionId: string;
  title?: string;
  idempotencyKey: string;
}

interface QuickCreateResult {
  featureId: string;
  recordId: string;
  targetRoute: string;
}
```

- `open-route` 只打开功能自己的创建页面，不通过主体提交业务数据。
- `inline-title` 只接受统一的短标题输入；更复杂的字段必须进入功能页面处理。
- `GET /api/v1/workbench/quick-actions` 在 Session 有效时只返回当前可见、具有 `create` 运行时能力的动作定义。
- `POST /api/v1/workbench/quick-actions/{featureId}/{actionId}` 调用对应提供者，执行 Session、工作区、输入和幂等键校验。
- 运行时能力不包含 `create` 时，主体隐藏该功能的快速创建动作。

#### 8.5.3 通知发布契约

```ts
interface WorkbenchNotificationInput {
  notificationId: string;
  audience: {
    workspaceId: string;
    userId: string;
  };
  source:
    | { kind: 'feature'; featureId: string }
    | { kind: 'system'; area: 'backup' | 'storage' | 'security' | 'application' };
  type: string;
  severity: 'info' | 'warning' | 'error';
  title: string;
  summary?: string;
  occurredAt: string;
  targetRoute?: string;
  requiresAction: boolean;
}

type WorkbenchNotification = Omit<WorkbenchNotificationInput, 'audience'> & {
  readAt?: string;
};
```

功能和共享平台通过 `NotificationService.publish(input)` 写入通知，不直接修改通知表，也不要求引入消息队列。功能通知使用 `feature` 来源，备份、存储和安全等平台通知使用受限的 `system` 来源。通知发布必须明确给出固定所有者的 `workspaceId` 和 `userId`；后台任务使用受限的系统身份并显式选择该工作区所有者。`GET /api/v1/workbench/notifications` 验证 Session 后返回固定所有者通知，并移除内部 `audience` 字段；已读操作使用独立更新接口。通知服务负责校验唯一 `notificationId`、工作区归属和目标路由。

### 8.6 注册来源与数据通路

固定注册点各自承担不同责任，不重复维护同一份展示数据：

| 来源               | 唯一负责内容                                                         | 与其他来源的关系                                   |
| ------------------ | -------------------------------------------------------------------- | -------------------------------------------------- |
| Web 功能目录表     | 名称、图标、说明、分类、关键词、路由和主体能力声明                   | 是功能汇总页和侧边栏的静态展示事实来源             |
| Web 路由注册       | 将目录表中的路由连接到功能页面                                       | 必须引用目录表中已有的 `featureId`，不能另建元数据 |
| API 功能注册       | 注册业务路由、运行状态、工作台只读贡献、搜索、快速创建和通知发布能力 | 使用同一个 `featureId`，不维护图标和展示说明       |
| OpenAPI 与生成 SDK | Web 与 API 之间的请求和响应类型                                      | 由已注册 API 生成，不手写第二套传输类型            |

运行时数据通路固定为：

```text
Web 功能目录表 ──→ 主体静态导航与功能方格
API 功能注册 ────→ /api/v1/workbench/features ──→ 功能运行状态
功能贡献提供者 ──→ /api/v1/workbench/overview ──→ 总览核心区与摘要区
摘要静态定义 ────→ /api/v1/workbench/overview/definitions → 编辑总览
总览显示偏好 ────→ /api/v1/workbench/preferences/overview → 可选摘要 blockIds
功能搜索提供者 ──→ /api/v1/workbench/search ────→ 全局搜索结果
快速创建提供者 ──→ /api/v1/workbench/quick-actions → 创建结果或功能创建页
NotificationService → /api/v1/workbench/notifications → 通知中心
OpenAPI ─────────→ 生成客户端 SDK ─────────────→ Web 调用
```

`GET /api/v1/workbench/features` 在 Session 有效时返回当前工作区的功能运行状态，不重复返回图标、说明和分类。CI 中的注册一致性测试必须检查 `featureId`、路由和 `blockId` 全局唯一，验证 `blockId` 使用所属 `featureId` 作为前缀、Web 目录项引用有效，并确认声明了总览、搜索、快速创建或通知能力的可见功能具有对应 API 提供者或共享服务接入。任何一项不一致都阻止构建或发布。

### 8.7 边界强制

| 约束                              | 强制方式                                 |
| --------------------------------- | ---------------------------------------- |
| 主体不导入功能内部文件            | ESLint import boundary                   |
| 功能定义字段完整                  | TypeScript 类型检查和注册测试            |
| 所有可见功能出现在汇总页          | 功能目录表、运行时状态和组件测试         |
| Web 与 API 使用一致的 `featureId` | 注册一致性测试                           |
| 总览局部失败隔离                  | 聚合服务测试和 Web 组件测试              |
| 隐藏摘要只发现、不取数            | 定义接口、偏好接口和聚合请求测试         |
| 摘要标识全局唯一                  | `blockId` 格式和注册唯一性测试           |
| 搜索、快速创建和通知能力声明真实  | API 提供者注册测试和 OpenAPI 契约测试    |
| 运行状态组合合法                  | 状态矩阵类型检查或单元测试               |
| 通知具有明确受众                  | NotificationService 工作区和后台任务测试 |
| 每个业务入口要求 Session          | API 认证策略注册检查                     |
| 新功能不重写稳定主体              | 代码评审路径检查和回归测试               |

## 9. 视觉设计基线

### 9.1 视觉方向

主体采用“冷静、克制、信息清楚”的效率工具风格：工作内容比导航更醒目，颜色主要承担操作和状态含义，不使用营销页式渐变、大标题或装饰性卡片墙。

### 9.2 色彩令牌建议

以下色值用于确定设计方向，最终实现需要进行对比度检查后固化。

```css
:root {
  --color-bg: #f5f7f6;
  --color-surface: #ffffff;
  --color-surface-muted: #eef2f0;
  --color-text: #17201c;
  --color-text-secondary: #59645f;
  --color-border: #dce3df;
  --color-accent: #176b5b;
  --color-accent-hover: #125448;
  --color-success: #237a4b;
  --color-warning: #946200;
  --color-danger: #b42318;
  --color-info: #2b62a3;
}

[data-theme='dark'] {
  --color-bg: #0f1412;
  --color-surface: #171d1a;
  --color-surface-muted: #202824;
  --color-text: #eef4f1;
  --color-text-secondary: #a5b0aa;
  --color-border: #303b35;
  --color-accent: #68d3ba;

```

### 9.3 字体与数据

- 中文优先使用 `Noto Sans SC`，西文和数字可使用 `Geist Sans`，并配置可靠的系统回退字体。
- 正文以 `14–16px` 为主，辅助标签 `12–13px`，区块标题 `16–20px`，页面标题 `24–28px`。
- 倒计时、时间、统计数字使用等宽数字特性，避免数值变化导致布局跳动。
- 文案使用直接的产品语言，例如“最近备份”“即将到来”“查看全部”，不使用宣传口号。

### 9.4 间距、圆角和层级

- 使用 `4px` 基础间距网格。
- 常用间距为 `8px、12px、16px、24px、32px`。
- 控件圆角以 `8px` 为主，较大交互方格使用 `12px`。
- 主体优先使用背景层次和轻边框；仅对悬浮层、菜单和可点击方格使用轻阴影。
- 嵌套控件保持同心圆角关系，避免外层和内层圆角互相冲突。
- 图标统一采用同一套线性图标库，默认不添加装饰性彩色底板。

## 10. 交互与可访问性

### 10.1 通用要求

- 所有可点击元素都有悬停、聚焦、按下、禁用和加载状态。
- 键盘可以访问导航、功能方格、搜索结果、总览摘要和菜单。
- 当前页面、状态和错误不能只通过颜色表达。
- 手机触控目标不小于约 `48 × 48px`，相邻目标保留足够间距。
- 图标按钮提供可读名称；摘要中的图表或进度提供文本等价信息。
- 支持浏览器缩放和系统字体放大，不以固定高度裁切关键文字。
- 动效只用于解释展开、切换和位置变化，并遵循减少动态效果偏好。

### 10.2 PC 快捷操作

建议提供：

| 操作                   | 建议快捷方式                   |
| ---------------------- | ------------------------------ |
| 打开全局搜索或命令入口 | `Ctrl/Cmd + K`                 |
| 快速创建               | `Ctrl/Cmd + N`，再选择动作     |
| 返回总览               | 可配置，不占用浏览器常用快捷键 |
| 关闭覆盖层或抽屉       | `Esc`                          |

快捷键必须在设置或命令入口中可发现，不能作为唯一操作方式。

### 10.3 导航连续性

- 从总览摘要进入功能后，返回应恢复总览滚动位置。
- 从功能汇总页打开功能后，浏览器返回应恢复搜索和分类筛选。
- 通知和搜索结果跳转需要保留来源，允许用户回到之前上下文。
- 删除、覆盖、恢复等高风险操作不在总览摘要中直接执行。

## 11. 性能与可靠性要求

- 应用壳和主体导航优先加载，不能等待所有功能摘要完成后才显示页面。
- 总览聚合查询并行执行，单个来源设置超时和独立错误结果。
- 首屏只请求当前可见摘要所需数据；隐藏摘要不持续轮询。
- 功能图标使用可缓存的本地资源或统一图标包，不逐个请求不稳定外部资源。
- 全局搜索分阶段返回：功能和动作立即可用，业务内容结果随后出现。
- 总览刷新保留已有数据，使用更新时间提示，避免整页闪烁为空。
- 工作台偏好保存失败时保留当前界面并给出重试，不直接丢失用户排序。

## 12. 隐私与安全要求

- 系统只有一个固定 `owner`，不提供注册、多用户、角色或按功能授权。
- 除 `/login` 和健康检查外，所有主体页面和业务 API 都要求有效 Session。
- 用户说明业务数据不包含敏感内容，但密码、Session、数据库口令和备份密钥仍属于秘密，不能进入前端包、日志或普通导出。
- Session 失效、退出或密码修改后，已有 API 缓存必须失效并回到登录页。
- 通知、搜索和最近内容不得展示密码、Session 标识、密钥或附件完整正文。
- 工作台偏好只保存功能标识、顺序和显示状态，不复制业务内容。
- 所有修改请求必须通过 CSRF Token 和同源检查；不能只依赖 `SameSite` Cookie。
- PWA 只缓存静态资源，不缓存登录后的 API 业务响应和 Session 信息。
- 密码修改和服务器重置密码必须撤销全部 Session Family；“退出其他会话”必须撤销除当前 Family 外的全部 Family。

## 13. 验收标准

### 13.1 应用壳

- [ ] 未登录访问业务路由会进入登录页，登录后安全返回原站内目标。
- [ ] 登录页固定并预填 `owner`，不存在注册、多账户或公开找回密码入口。
- [ ] “记住此设备”能在同一浏览器关闭重开和服务重启后保持登录，并遵守 180 天空闲、365 天绝对期限、每 24 小时至多续展一次和每 7 天轮换规则。
- [ ] 轮换后的旧标识只在 2 分钟并发宽限期内有效；退出、撤销、修改密码和重置密码不保留宽限期。
- [ ] 用户可以查看、区分、改名并撤销登录会话；修改或重置密码后全部 Session Family 立即失效。
- [ ] 总览和功能汇总页始终存在明确入口。
- [ ] PC、平板和手机宽度下均能完成导航，不出现关键入口被遮挡。
- [ ] 侧边栏功能可以隐藏、重新显示、调整顺序和恢复默认顺序，刷新后保持结果。
- [ ] 页面刷新、直接链接和浏览器前进后退保持有效。
- [ ] 应用壳错误不会被某个功能页面的局部错误替代。

### 13.2 总览页

- [ ] 能同时展示来自至少三个真实功能的公开摘要。
- [ ] 当前关注、即将到来和功能摘要具有明确优先级。
- [ ] 每条摘要能够识别来源并进入对应功能。
- [ ] 单个摘要失败时，其他摘要和主体导航仍可使用。
- [ ] 用户可以显示、隐藏和调整可选摘要顺序。
- [ ] 手机端不依赖横向滚动查看核心信息。
- [ ] 数据加载、空数据、过期和错误状态都有明确表现。

### 13.3 功能汇总页

- [ ] 当前工作区的所有可见功能在“全部功能”中恰好出现一次。
- [ ] 每个功能使用一个清晰方格，包含名称、图标和用途说明。
- [ ] 搜索可以通过名称、说明和关键词找到功能。
- [ ] 分类筛选和清除筛选行为明确。
- [ ] 调整侧边栏顺序不会改变功能汇总页的完整性和默认目录顺序。
- [ ] 开发中、需要配置和不可用状态不会被误认为已完成可用。
- [ ] 手机端两列方格具有足够触控面积和可读文字。

### 13.4 新功能接入

- [ ] 新功能通过固定定义和注册点进入功能汇总页。
- [ ] 支持摘要的功能可以通过公开契约进入总览。
- [ ] 新功能不需要修改总览布局组件、侧边栏组件和功能方格组件。
- [ ] 主体不导入新功能的内部 Repository、Store、Query Key 或私有组件。
- [ ] 移除新功能注册后，主体和其他功能仍能构建和运行。

### 13.5 可访问性与视觉一致性

- [ ] 键盘可以访问所有主体页面核心操作。
- [ ] 焦点状态清晰且不会被覆盖层截断。
- [ ] 状态信息不只依赖颜色。
- [ ] 文本放大后不丢失核心操作。
- [ ] 功能方格和总览摘要使用统一字体、间距、圆角和状态样式。
